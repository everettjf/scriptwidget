# Hydration Goal iCloud

This is a separate, opt-in iCloud example. It does not change or migrate records from **Hydration Goal**. Install the complete package, then open its **iCloud Data** menu in My Widgets and create a data store. On another device, install the same package and connect it to the **same store ID**. Both devices need a ScriptWidget build supporting Runtime 1.5 and the same iCloud account. Use the widget's **Sync** button or the app's **Sync Now** control to request an exchange; iCloud delivery and WidgetKit refresh can be delayed.

Each **+ glass** tap saves an immutable, timestamped event in `hydration.json` under `iCloud Drive/ScriptWidget/WidgetData/<store ID>/`. The `at` field records the device clock in UTC and `day` is the recording device's local calendar day. The widget derives its daily total and seven-day history from those events. If two devices add glasses while offline, a later user action unions events by ID and resolves the observed fork. Normal rendering only reads cached data; it never writes or claims that another device has received a change. The optional widget parameter is `{"goal":8,"glassML":250}`.

This example is **add-only**. It intentionally has no Reset or Undo: deleting or reversing an event across offline devices needs a separate conflict policy. The existing native **Records & Configuration** backup does not cover this cloud document. Existing local hydration history is not imported, and old daily totals cannot be turned into individual tap times. Do not edit or delete revision files directly; copy them if you need a personal archive.

The current iCloud JSON store is bounded to 256 immutable revisions and 2 MiB across all documents, with no automatic compaction. Every tap and conflict resolution consumes a revision. When it reaches the limit, new writes fail while existing revisions remain. This is a bounded example, not an unlimited long-term health log. Before using it for sustained tracking, export an archive and use a future record-sync capability with a retention/compaction design.
