# ScriptWidget Windows 版：开发计划

状态：计划稿，2026-11-16。尚未写任何 Windows 代码，也没有在 Windows 机器上运行过任何东西。依据是 [Windows 可行性调研](feasibility.md)；Linux 版已搁置（2026-11-16 决定），本计划不再以和 Linux 共用代码为目标。

标注约定：**[已核实]** 调研时直接读到官方页面、项目源码或本仓库文件；**[二手]** 第三方文章或搜索摘要；**[待验证]** 没有可靠来源，或必须在 Windows 真机上确认。

## 1. 目标

同一个 Package 2.0 小组件（同一份 `main.jsx` 和 `widget.json`）在 Windows 11 的桌面上运行，并且能装到同一个人的 iPhone 或 Android 手机上。

三条产品原则：

1. **主形态是我们自己画的桌面小组件。** Windows 的官方小组件面板只接受 Adaptive Card，不能自绘，欧洲经济区之外没有 HTML 小组件，也没有官方的桌面位置 [已核实]。官方面板最多是后期的附加出口。
2. **面向普通用户，不是只面向会写代码的人。** 第一次打开就能从模板里放一个小组件到桌面上；写代码是进阶用法。
3. **Windows 版免费，通过微软商店分发。** 这是在中国的个人开发者唯一不花钱、安装时不弹警告的组合 [已核实，见调研]。收入仍来自手机和 Mac 应用。

## 2. 技术选型

| 部分 | 选择 | 说明 |
| --- | --- | --- |
| 语言 | C++20，MSVC | 核心按可移植的方式写，但不为其他平台做任何额外工作 |
| 构建 | CMake，x64 和 ARM64 | GitHub Actions 的 Windows 机器上构建和测试 |
| 脚本引擎 | QuickJS-NG 0.18.0，用仓库里已有的源码（`Android/core/src/main/cpp/quickjs`） | 和 Android 同一份源码。上游称把 Windows 和 MSVC 当作一等平台 [二手]；能否直接编过是阶段 0 的第一件事，不行就改用 clang-cl |
| 绘制 | Direct2D | 圆角、渐变、阴影、裁剪、路径、图片 |
| 文字 | DirectWrite | 度量和绘制是同一套；中日韩文字、字体回退、彩色表情由系统处理 |
| 图片解码 | WIC（系统自带） | PNG、JPEG、GIF、WebP |
| `Intl` | 系统的 `icu.dll` | Windows 10 1903 起自带，导出 Android 那套 `Intl` 补丁需要的接口 [已核实] |
| 网络 | WinHTTP | 由我们自己的策略层决定放行与否 |
| 窗口 | Win32 分层窗口 | 每个小组件一个窗口，只负责贴位图和接收点击 |
| 管理界面 | WebView2 里加载现有的 Web Studio，按需打开，关掉即释放 | 不进入全天运行的路径 |
| 打包 | MSIX，微软商店 | 微软代签名和托管；`StartupTask` 负责开机启动 |

不采用的：

- **常驻的 WebView2。** 用它可以直接复用浏览器渲染器，不用写画笔，但它会带起一组浏览器进程全天挂着。微软没有公布内存数字 [已核实]。
- **WinUI 3。** 托盘加几个设置项用不到它，而且会带来 Windows App SDK 的体积和依赖。管理界面用现成的 Web Studio 更省。
- **Rust、Skia。** 只做 Windows 时没有必要。

## 3. 可以直接复用的

| 资产 | 位置 | 用法 |
| --- | --- | --- |
| 执行内核 | `Web/preview-engine/src/kernel.js` | 原样在 QuickJS 里运行 |
| 布局和渲染器 | `Web/preview-engine/src/render/` | 原样运行；文字宽度通过 `measurer` 接口向原生侧询问 |
| 在 QuickJS 里跑渲染器并记录节点的入口 | `Android/core/src/main/js/render/entry.mjs` | 不含 Android 专有代码，直接用 |
| QuickJS 宿主脚本（收起原生入口、`Intl` 子集、启动函数） | `Android/core/src/main/js/android-host.js` | 大部分与平台无关。抽成共用文件，Android 和 Windows 都用它 |
| 清单校验、包准备、时间线、JSX 编译 | `Web/preview-engine/src/{package,prepare.js,timeline.js,compiler.js}` | 和 Android 一样打成一个包在 QuickJS 里运行 |
| 打包这些 JS 的脚本 | `Android/scripts/build-shared-js.mjs` | 照它写一个输出到 `Windows/` 的版本，或把它改成两个平台共用 |
| 原生调用的 C 接口写法 | `Android/core/src/main/cpp/scriptwidget_jni.c`（336 行，含内存上限、栈上限、中断） | 去掉 JNI，改成普通的 C++ 调用 |
| 画笔的逻辑 | `Android/core/.../render/*.kt`，约 1,400 行 | 照着 `Canvas` 写的，Direct2D 的接口基本一一对应。**逐个函数移植，这是最大的一块新工作** |
| 164 棵一致性树 | `Web/preview-engine/test/parity/native-trees.json` | 运行时的验收门槛 |
| Web Studio | `Web/studio/` | 管理界面：编辑、预览、模板 |
| 模板和 Gallery 索引 | `Shared/.../Script.bundle/template/`、`Gallery/` | 随应用打包；Gallery 沿用现有的校验规则 |

改动共用的 JS（宿主脚本、构建脚本）会影响 Android，改完要跑 Android 的 JVM 和设备测试。

## 4. 架构

```
ScriptWidget.exe（常驻，托盘）                swrunner.exe（按需启动，受限）
┌─────────────────────────────┐              ┌──────────────────────────────┐
│ 小组件窗口：贴位图、收点击   │   元素树     │ QuickJS：内核 + 包代码        │
│ 调度：时间线、定时刷新       │ ◀─────────── │ 只能通过主进程提供的接口       │
│ 画笔：QuickJS 跑渲染器       │   请求        │ 访问网络、存储、文件           │
│        + Direct2D/DirectWrite│ ───────────▶ │ 内存上限、超时中断            │
│ 包存储、权限、网络策略       │              └──────────────────────────────┘
│ 托盘菜单                    │
└──────────────┬──────────────┘
               │ 按需
       管理窗口（WebView2 + Web Studio）
```

### 4.1 两个进程

- **主进程 `ScriptWidget.exe`**：只运行我们自己的代码。渲染器在这里的 QuickJS 里跑，输入是元素树（数据），不是包代码，和 Android 的做法相同。
- **执行进程 `swrunner.exe`**：运行不可信的包代码。QuickJS 不暴露任何系统接口，网络、存储、文件都要向主进程请求，由主进程按清单里声明的权限决定。执行完就退出。

第一版靠 QuickJS 的内存上限、栈上限和中断，加上进程隔离。把执行进程放进 AppContainer 并用作业对象限制内存和 CPU，放在阶段 5；AppContainer 可以从普通 Win32 程序启动 [已核实]，但具体做法没有试过 [待验证]。

### 4.2 桌面窗口

采用 Rainmeter 的做法：顶层窗口保持在所有普通窗口之下，而不是挂到桌面的内部窗口上。后者（Lively 的做法）在 Windows 11 24H2 上被系统改动弄坏过一次 [已核实，读过两者的源码]。两种做法都依赖系统未公开的行为。

- 窗口样式：分层（逐像素透明）、不进任务栏和 Alt-Tab、点击不抢焦点。用 Direct2D 画到内存位图，再整幅更新到窗口。
- 每个显示器按自己的缩放比例出图；窗口移到另一个显示器或缩放变化时重画。
- 位置按显示器保存；显示器拔掉后小组件回到主显示器，插回去后恢复。
- 编辑模式下可以拖动、对齐网格、调整尺寸；平时锁定，点击只触发小组件自己的动作。
- 点击时按坐标查可点击区域，把一个编号交给主进程，由主进程从自己保存的动作表里查出动作。窗口消息里不带动作内容。

要在真机上确认的 [待验证]：按 Win+D（显示桌面）后小组件是否还在；资源管理器重启后是否恢复；睡眠唤醒后定时是否正常；多个虚拟桌面上是否都出现；全屏应用和游戏运行时是否让路。

### 4.3 托盘和管理界面

- 托盘菜单：打开管理窗口、添加小组件、编辑模式、暂停刷新、退出。
- 管理窗口加载打包在应用里的 Web Studio。它需要一层和原生的桥接：列出和安装包、读写包文件、把某个包放到桌面上。iOS 和 Mac 的应用里已有同样用途的桥接，照它的接口做。
- Web Studio 里的预览用的是浏览器渲染器，桌面上用的是 Direct2D 画笔，两者会有细微差别。保存后桌面上的小组件立即刷新，以桌面上的为准。
- 第一版不做内置的 AI 生成，所以不保存任何 API 密钥。商店政策对个人账号的应用要求密钥类信息还有额外限制（10.8.3）[已核实]，以后要做时再评估。

### 4.4 平台契约

- `$system.platform()` 返回 `"windows"`。
- 尺寸：small、medium、large、extraLarge，点数沿用 Mac 的配置（170×170、329×170、329×345、639×345），再乘以显示器缩放。没有锁屏尺寸。
- 没有对应物的能力返回 `[unsupported_platform]`。所有差异写进 `docs/platform-support.md` 新增的 Windows 一列。

| API | 第一版 | 说明 |
| --- | --- | --- |
| `$device`、`$system`、`$storage`、`$file`、`fetch`、`$http`、`$xml` | 支持 | 权限、域名声明、私有地址拒绝、预算和其他平台相同 |
| `$dataSource` | 支持 | 逻辑在共用的 JS 里 |
| 时间线、按钮、开关 | 支持 | 主进程自己调度 |
| `$weather` | 待定 | 取决于 Android 用的数据来源能否照搬，本次没有查 |
| `$music` | 之后 | 系统的媒体会话接口可以读到正在播放的内容 [待验证] |
| `$notifications`、`$location` | 之后 | 有系统接口，需要包身份和用户授权 [待验证] |
| `$calendar`、`$reminders`、`$health`、`$photos`、`$contacts`、`$home`、`$icloud`、`$alarms`、`$maps`、`$services` | 不支持 | |
| Live Activity、Control Widget、Siri 动作、推送刷新 | 不支持 | |

依赖健康、日历数据的小组件在 Windows 上只能显示"此平台不支持"。模板库里要把这类模板标出来或不显示。

## 5. 发到手机

和之前的设想相同，只是入口从终端换成管理窗口。

1. 在管理窗口里点"发到手机"，应用把包打成 `.swt`，在局域网上临时提供一次下载，并显示二维码。二维码的内容是 `scriptwidget://import?...`，带下载地址、大小和 SHA-256。
2. 手机扫码打开应用，下载、核对，然后走现有的不可信压缩包导入流程，用户确认后安装。

现状和未决事项：

- Android 能打开 `.swt` 并注册了 `scriptwidget://`；iOS 注册了 `scriptwidget://`，但现在能处理哪些地址没有核实 [待验证]。两个应用都要新增 `import` 处理，这是新增契约，要有安全评审和测试。
- Windows 上开监听端口会触发防火墙提示 [待验证]。备选是反过来由电脑连手机：iOS 应用已有 Web Studio 配对（手机开服务，电脑用六位码连接）[已核实]，Android 有没有没查。
- 第一版先提供最简单的办法：导出 `.swt`，用户自己传到手机。

## 6. 安全

脚本、导入的压缩包、Gallery 内容、网络响应仍然全部视为不可信。Windows 上要重新落实并各自配测试的不变量：

- 包路径规范化，拒绝穿越、绝对路径、符号链接、反斜杠、大小写冲突。Windows 还要拒绝保留设备名（`CON`、`NUL` 等）、结尾的点和空格、备用数据流（文件名里的冒号）、盘符和 UNC 路径。
- 压缩包的条目数、单文件大小、展开总大小限制；先预检再解压；唯一的临时目录；事务式安装。
- 网络需要 `network` 权限和匹配的 `networkDomains`；拒绝私有、本地和回环地址，包括解析之后的地址；请求和响应预算。
- `$file` 限制在包内，`$storage` 按包隔离并有上限。
- 清单存在但格式错误时直接失败。
- C++ 侧处理不可信输入的代码尽量少：清单和包的校验继续用共用的 JS 在 QuickJS 里跑；压缩包解析用成熟的库并开启边界检查；CI 里用 AddressSanitizer 跑测试。
- 管理窗口的 WebView2 只加载应用自带的页面，桥接接口只对这个来源开放。
- 不记录凭据、完整的敏感响应和用户文件内容。

## 7. 分发

- **微软商店，MSIX，个人账号。** 注册免费，微软代签名，审核最长三个工作日 [已核实]。
- **商店政策。** 现行版本 7.20 没有禁止解释器；相关条款是 10.2.2，禁止用动态代码把产品变成描述之外的东西 [已核实]。"在描述里写清楚应用会运行用户编写的小组件脚本就合规"是我们对条文的解读，没有先例。提交前可以直接问微软。
- **GitHub Releases** 同时提供 MSIX。商店外安装的包需要受信任的证书签名；对中国的个人开发者，便宜的签名服务不开放，证书约 219 美元一年 [已核实]。所以商店外的包先不签名或不提供，由你决定。
- **个人账号的限制。** 政策把个人账号和"与其业务无关的活动"联系在一起（10.14）[已核实]，对一个免费、不经微软收款的应用影响不大，但措辞含糊。

## 8. 阶段

估算是单人加 AI 辅助的粗估，没有依据可以校准，只用来排顺序。

### 阶段 0：验证（1 到 2 周）

前四项任何一项不通过就停下来重新评估。

| 事项 | 通过标准 | 谁做、在哪做 |
| --- | --- | --- |
| 注册微软商店个人账号并保留应用名 | 用中国大陆证件完成身份验证 | 你本人。2026 年有论坛个例反映验证卡住 [二手] |
| QuickJS 用 MSVC 编译，运行共用内核 | 164 棵一致性树逐字节相同；内存上限和超时中断生效 | CI 的 Windows 机器 |
| Direct2D 画笔的保真度 | 10 个有代表性的模板和浏览器预览截图对比，差异在 Android 当时接受的范围内；中文、表情、图表各至少一个 | CI 出图，人看 |
| 置底窗口的行为 | Win+D、资源管理器重启、睡眠唤醒、多显示器不同缩放下表现正常 | Windows 11 真机或虚拟机 |
| 商店政策 | 向微软确认 10.2.2 对内嵌脚本引擎的适用 | 你本人提问，我起草 |

### 阶段 1：运行时（2 到 3 周）

`Windows/` 目录和 CMake 工程；QuickJS 封装和宿主脚本；执行进程和它与主进程的协议；包存储和校验；存储、文件、网络模块及权限检查；完整的画笔；一个只在命令行下工作的 `render` 模式，用来在 CI 里出图。

完成标准：CI 里一致性树、安全测试全部通过；`render` 能渲染全部不依赖系统数据的内置模板，并和基准图做回归对比。

### 阶段 2：桌面（2 到 3 周）

小组件窗口、托盘、编辑模式、位置和尺寸保存、时间线调度、按钮和开关、多显示器和缩放、开机启动。

完成标准：在 Windows 11 上，从本地文件夹添加的多个小组件能放在桌面上、按时刷新、响应点击，注销重新登录后恢复原位。

### 阶段 3：管理界面和商店（2 到 3 周）

WebView2 管理窗口和桥接；模板库；导入和导出 `.swt`；首次启动引导；MSIX 打包；商店的截图和说明；先用商店的小范围发布做内测。

完成标准：一个没有用过 ScriptWidget 的人，从商店安装后三分钟内能把一个模板小组件放到桌面上并改掉它的一处文字。

### 阶段 4：发到手机（2 到 3 周）

二维码传输或反向配对；iOS 和 Android 的 `import` 处理及安全测试；发布包含它的手机版本。依赖两个应用商店的审核。

### 阶段 5：之后

官方小组件面板的提供方（一个通用定义，每个实例绑定一个脚本，整幅位图加按钮行；`data:` 图片能否使用要先验证 [待验证]）；执行进程的 AppContainer 和作业对象；`$music` 等系统接口；Gallery。

## 9. 测试

- **CI（GitHub Actions 的 Windows 机器，x64 和 ARM64）**：一致性树、包和压缩包的安全测试、网络策略测试、`render` 截图回归、AddressSanitizer。
- **真机清单**：桌面窗口的各种行为、缩放和多显示器、睡眠唤醒、开机启动、从商店安装和升级。每次记录到 `docs/windows/testing.md`，写明 Windows 版本和机器。
- **共用代码**：改动 `Web/preview-engine` 或共用的宿主脚本后，要跑预览引擎自己的测试、Android 的测试和 Windows 的测试。

## 10. 需要你提供或决定的

1. **一个 Windows 11 环境。** 这台 Mac 上可以用 Parallels 装 Windows 11 Arm 版，它是微软在 Apple 芯片上唯一授权的方式 [已核实]。编译和自动测试我可以通过 CI 完成并核对结果；窗口行为、缩放、睡眠唤醒这些只能在真实的 Windows 桌面上看，没有这个环境我不能声称它们验证过。x64 机器上的表现也要另找机器确认。
2. **微软商店个人账号。** 注册和身份验证要你本人做。这是否决项里唯一现在就能做、不花钱的一项。
3. **是否接受改两个手机应用来支持扫码导入。** 阶段 4 的前提。
4. **商店外是否提供安装包。** 不签名会弹警告，签名要花钱。
5. **优先级。** 仓库当前的优先事项是稳定已有契约和把 Android 送上 Google Play。阶段 0 可以放在 Android 封闭测试的 14 天等待期里。

## 11. 不做的事

- Linux 版（已搁置，计划保留在 [docs/linux/plan.md](../linux/plan.md)）。
- Windows 10。
- 第一版里的官方小组件面板、锁屏、内置 AI、Gallery。
- 新的 JSX 标签或只有 Windows 才有的能力。
- 在 Windows 版里收费。
