## 实测发现、还没有处理的问题

1. **每轮都重写整个文件。** 一个小改动显示为“22 行有变化”，慢、费 token，也容易改坏没有要求改的地方。
2. **模型会编造不存在的属性**，例如 `<date style="weekday">`。运行时不报错，只是显示成别的内容，所以自动修复发现不了。
3. **Mac 上没有看到逐字输出的文字**，虽然流式请求已经接入。需要确认是提供方没有分段返回，还是界面没有显示。
4. `LibrarySessionExecutionTests` 里的几个用例在 CI 的慢机器上会超过 5 秒限时，偶发失败。与 AI 无关，但会挡住合并。

## 第三阶段：改得更省、更准、看得清

建议顺序如下，前一项是后一项的前提。

### 3.1 只改局部

- 回复格式增加“修改”形式：若干段“原文 → 新文”，由 App 应用到当前版本的源码上。整文件回复继续支持，第一轮和大改动仍然用它。
- 应用规则放在共享代码里，Swift 和 Kotlin 各一份，行为一致：原文必须在当前源码中恰好出现一次；找不到或出现多次时这一轮按失败处理并进入修复，不猜测。
- 应用后的结果和整文件回复走同一条路：同样的校验、同样的运行限制、同样的权限。模型输出仍然是不可信内容。
- 完成标准：评测里的小改动，变化行数明显少于现在，成功率不下降。

### 3.2 属性校验

- 在运行之前，用编辑器已有的 API 清单（`Editor/editorfe/src/scriptWidgetAPI.js` 对应的数据）检查标签名和属性名，未知的名字作为错误发回模型修复。
- 只检查名字是否存在，不改变运行时的行为；运行时的 JSX 开关仍然是唯一的依据，清单与它不一致时以运行时为准并修清单。
- Android 独有的 `<list>` 和 `material.` 颜色要在 Android 的清单里有，否则会被误报。

### 3.3 差异视图

- 每个版本可以查看相对上一版改了哪几行。Mac 先做，放在对话的版本行里；Android 之后做。
- 差异在本地计算，不发给提供方。

### 3.4 用量提醒

- 显示这段对话已经用掉的 token。接近上下文上限或单轮花费明显变大时提示，并建议从当前版本开一段新对话。
- 历史的裁剪规则保持现在的做法：不在当前路径上的轮次不发送。

### 3.5 多轮评测

- 在现有的 [AI 质量测试](ai-quality-testing.md) 里加入连续几轮修改的题目：生成、改一处、再改一处、回到旧版本再改。
- 记录每轮的成功与否、修复次数、变化行数和 token，用来比较提示词和模型的改动。
- 真实提供方的评测只在设置了环境变量时运行，密钥只通过环境变量传入，不写进命令、文件或日志。

## 第四阶段：iPhone 和 iPad

- 用和 Mac 相同的共享代码（`AIConversation`、`AIConversationStore`、`AIConversationSession`），只写界面。
- iPhone 参考 Android 的一屏布局：预览在上，对话在中，输入框贴着键盘。iPad 参考 Mac 的左右布局。
- 现有的单次请求加 Refine 的页面在对话可用后移除。
- 需要在模拟器和真机上验证，包括键盘、横竖屏和小组件扩展的内存不受影响。

## Android 与 Mac 的差距

记在 [`docs/android/TODO.md`](android/TODO.md)：回复不逐字输出、一次只看一个尺寸、编辑器里没有 Copilot。第三阶段的 3.1、3.2 要同时在 Kotlin 里实现。

## 不变的约束

- 密钥只存在 Keychain（Android 为 Keystore 加密的文件），不进入提示词、包、日志和偏好设置。
- 生成的代码不可信，按与其他 Widget 相同的运行限制和权限运行。
- Skills 只补充提示词，不授予工具或权限。
- 存在但读不出来的 `widget.json` 一律按失败处理，不当作没有。
