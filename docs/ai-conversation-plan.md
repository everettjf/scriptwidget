## 实测发现的问题

1. **每轮都重写整个文件。** 已处理：见下面 3.1。成批评测里 10 轮后续修改平均改动 2 行。
2. **模型会编造不存在的属性**，例如 `<date style="weekday">`。已处理：见下面 3.2。
3. **Mac 上没有看到逐字输出的文字**，虽然流式请求已经接入。已查清，不是缺陷：这台 Mac 上配置的服务商是 Apple Private Cloud Compute，它一次返回整段回复，不分段。兼容 OpenAI 的服务商才会逐字显示；这一条在 iPhone 模拟器上用本机的脚本服务看到了逐字输出，没有用真实服务商看过。
4. `LibrarySessionExecutionTests`、`RuntimeExecutionTests` 里的几个用例在 CI 的慢机器上会超过 5 秒限时，偶发失败；同一次运行里依赖预览的 AI 测试也会跟着失败。未处理：与 AI 无关，但会挡住合并，重跑可以通过。
5. **模型把 `<date>` 写进 `<text>` 里**（真实模型测试中出现），运行不报错但什么都不显示。已处理：属性校验现在会指出写在 `<text>`、`<date>`、`<image>`、`<icon>`、`<label>` 里面的标签，提示词里也加了一句。
6. **线性渐变不写 `startPoint`、`endPoint`**（真实模型测试中出现），结果只显示第一种颜色。部分处理：提示词里加了写法；运行时在缺少这两个值时的行为没有改，也没有校验。
7. **进度里写“第 2 次，共 4 次”**，而 Apple Private Cloud Compute 实际只给 3 次。已处理：次数按当前服务商显示。

## 第三阶段：做了什么

### 3.1 只改局部

- 有现成代码的轮次，模型可以用 `<<<<<<< SEARCH` / `=======` / `>>>>>>> REPLACE` 块只回复要改的地方；新 Widget 和修复仍然回复整份代码。
- 每段原文必须在当前代码里恰好出现一次。找不到或出现多次时整条回复作废，把原因发回模型并要求回复整份代码，不猜测。
- 应用后的代码和整份回复走同一条路：同样的运行、同样的限制和权限。
- 代码：`AISourceEdits.swift` 和 `AiSourceEdits.kt`，行为一致，测试互相对照。

### 3.2 属性校验

- Widget 运行之后，检查代码里的标签名、属性名，以及有固定取值的属性的值。有问题就把“写了什么、实际有什么”发回模型修复；最后一次尝试不拦，能运行的 Widget 保留。
- 名单由 `npm run docs` 生成：编辑器的 `scriptWidgetAPI.js` 加上网页渲染器的 `coverage.js`（后者的测试保证它覆盖原生代码读取的每个属性）。只有运行时确实按固定名单读取的属性才检查取值。
- 宁可漏报不误报：首字母大写的标签当作脚本自己的组件，计算出来的值不判断。仓库里所有模板、示例和 Gallery 的 Widget 都通过检查，这一条有测试。
- Android 独有的 `<list>` 只在 Android 的名单里。`material.` 颜色是取值，不在检查范围内。
- 代码：`AIJSXCheck.swift` 和 `AiJsxCheck.kt`。

### 3.3 差异视图

- 每个版本显示相对上一版增删了几行（“+3 −2”），点开看具体的行和前后各三行。Mac、iPhone、iPad、Android 都有。
- 在本机计算，不发给提供方。

### 3.4 用量提醒

- 单次请求约 30,000 token 以上、整段对话累计 300,000 token、版本满 30 个、轮次超过 12 轮时，在输入框上方提示。
- “Start New From Here” 从当前版本开一段新对话：只带这一个版本，不带历史。

### 3.5 多轮评测

- `Scripts/ai-conversation-quality.sh`：四段小对话（问候卡片、习惯打卡、时钟、中文卡片），共 14 轮，其中一轮先回到旧版本。记录每轮是否通过、修复次数、收发的 token、改动的行数。
- 同一套流程用脚本回复在常规测试里跑一遍，不需要密钥。

## 第四阶段：做了什么

- “Generate with AI” 在 iPhone 和 iPad 上是同一套对话，用的是 Mac 的共享代码（会话、存储、轮次列表）。
- iPhone：预览在上，对话在中，输入框贴着键盘，打字时预览缩小。iPad：对话在左，预览和三个尺寸在右。
- 原来“单次请求加 Refine”的两个页面已删除。
- 编辑器里的 Copilot 也改成了对话，从 Mac 的面板移植：AI 改的是副本，Apply 才写入文档，新域名先确认。
- 对话界面的文字加了简体中文（iPhone、iPad）。

## Android 原来的三项差距

已经补上：回复逐字显示；预览下方并排画出三个尺寸，点一下切换；编辑器里有“Improve with AI”按钮，保存后进入这个 Widget 的对话，应用后回到编辑器会显示新代码。手机上没有地方放编辑器旁边的面板，所以对话仍然是单独一屏。Pixel 6 上的界面测试覆盖了这三项，用的是脚本模型。

### 生成质量

- [ ] **`frame` 里写对齐方式**：成批评测里模型多次写出 `frame="max,center"`、`frame="max,leading"`、`frame="max,auto"`，而 `frame` 的第二个值本应是高度。先查运行时实际怎么处理，再决定是在提示词里说明、加进校验，还是两者都做。
- [ ] **线性渐变缺少 `startPoint`、`endPoint` 时只显示第一种颜色**：现在只在提示词里补了写法。要决定运行时是否给缺省方向；这是运行时行为的改动，要同时改网页渲染器和 Android，并说明兼容性。
- [ ] **评测只看代码不看画面**：通过不等于好看。可以接上现有单轮评测的截图和 OCR 那一套（见 [AI 质量测试](ai-quality-testing.md)）。
- [ ] **属性校验的范围**：现在管标签名、属性名、运行时按固定名单读取的那几个属性的取值，以及五个不能包含标签的标签。`alignment`、`font`、图表的 `type` 等没有检查，因为运行时接受的写法比清单多。

### 成本

- [ ] **每轮固定发送约 12,000 个 token**：规则和 API 参考每一轮都发，14 轮评测发了 17 万、只收回 6 千。看能不能缩短参考、只发用得到的部分，或者让支持的服务商缓存这一段。

- [ ] **CI 变慢的根因**：几个运行时测试在 GitHub 的 macOS 机器上会超过 5 秒限时，每次还不一样。现在靠失败后重跑（最多 3 次）绕开。要查清是机器、测试之间互相拖累，还是某一步确实慢；经常要重跑的测试按缺陷处理。

## 不变的约束

- 密钥只存在 Keychain（Android 为 Keystore 加密的文件），不进入提示词、包、日志和偏好设置。
