## 实测发现的问题

1. **每轮都重写整个文件。** 已处理：见下面 3.1。效果要用真实模型量。
2. **模型会编造不存在的属性**，例如 `<date style="weekday">`。已处理：见下面 3.2。
3. **Mac 上没有看到逐字输出的文字**，虽然流式请求已经接入。未处理：需要一个真实提供方才能确认是提供方没有分段返回，还是界面没有显示。
4. `LibrarySessionExecutionTests` 里的几个用例在 CI 的慢机器上会超过 5 秒限时，偶发失败。未处理：与 AI 无关，但会挡住合并。

## 第三阶段：做了什么

### 3.1 只改局部

- 有现成代码的轮次，模型可以用 `<<<<<<< SEARCH` / `=======` / `>>>>>>> REPLACE` 块只回复要改的地方；新 Widget 和修复仍然回复整份代码。
- 每段原文必须在当前代码里恰好出现一次。找不到或出现多次时整条回复作废，把原因发回模型并要求回复整份代码，不猜测。
- 应用后的代码和整份回复走同一条路：同样的运行、同样的限制和权限。
- 代码：`AISourceEdits.swift` 和 `AiSourceEdits.kt`，行为一致，测试互相对照。

### 3.2 属性校验

- Widget 运行之后，检查代码里的标签名、属性名，以及有固定取值的属性的值。有问题就把“写了什么、实际有什么”发回模型修复；最后一次尝试不拦，能运行的 Widget 保留。
- 名单由 `npm run docs` 生成：编辑器的 `scriptWidgetAPI.js` 加上网页渲染器的 `coverage.js`（后者的测试保证它覆盖原生代码读取的每个属性）。只有运行时确实按固定名单读取的属性才检查取值。
- 宁可漏报不误报：首字母大写的标签当作脚本自己的组件，计算出来的值不判断。仓库里所有模板、示例和 Gallery 的 Widget 都通过检查，这一条有测试。
- Android 独有的 `<list>` 只在 Android 的名单里。`material.` 颜色是取值，不在检查范围内。
- 代码：`AIJSXCheck.swift` 和 `AiJsxCheck.kt`。

### 3.3 差异视图

- 每个版本显示相对上一版增删了几行（“+3 −2”），点开看具体的行和前后各三行。Mac、iPhone、iPad、Android 都有。
- 在本机计算，不发给提供方。

### 3.4 用量提醒

- 单次请求约 30,000 token 以上、整段对话累计 300,000 token、版本满 30 个、轮次超过 12 轮时，在输入框上方提示。
- “Start New From Here” 从当前版本开一段新对话：只带这一个版本，不带历史。

### 3.5 多轮评测

- `Scripts/ai-conversation-quality.sh`：四段小对话（问候卡片、习惯打卡、时钟、中文卡片），共 14 轮，其中一轮先回到旧版本。记录每轮是否通过、修复次数、收发的 token、改动的行数。
- 同一套流程用脚本回复在常规测试里跑一遍，不需要密钥。

## 第四阶段：做了什么

- “Generate with AI” 在 iPhone 和 iPad 上是同一套对话，用的是 Mac 的共享代码（会话、存储、轮次列表）。
- iPhone：预览在上，对话在中，输入框贴着键盘，打字时预览缩小。iPad：对话在左，预览和三个尺寸在右。
- 原来“单次请求加 Refine”的两个页面已删除。

## 不变的约束

- 密钥只存在 Keychain（Android 为 Keystore 加密的文件），不进入提示词、包、日志和偏好设置。
- 生成的代码不可信，按与其他 Widget 相同的运行限制和权限运行。
- Skills 只补充提示词，不授予工具或权限。
- 存在但读不出来的 `widget.json` 一律按失败处理，不当作没有。
